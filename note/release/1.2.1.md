**崩溃修复版本**。修复玩家加入游戏时 `BEListener.onPlayerJoin` 抛异常的问题。

## 问题

玩家加入时控制台报错：

```
Could not pass event PlayerJoinEvent to ExoticGarden v1.2.0
java.lang.IllegalArgumentException: name cannot be null
    at org.bukkit.craftbukkit.CraftServer.getWorld(CraftServer.java:1386)
    at org.bukkit.Bukkit.getWorld(Bukkit.java:871)
    at com.be.utils.BEListener.onPlayerJoin(BEListener.java:28)
```

## 根因

[BEListener.onPlayerJoin](../src/main/java/com/be/utils/BEListener.java) 与
[SpawnCommand.onCommand](../src/main/java/com/be/command/SpawnCommand.java) 都写了：

```java
World world = Bukkit.getWorld(plugin.getConfig().getString("spawn.world"));
if (world == null) { return; }   // 期望“未设置出生点时静默跳过”
```

默认 [config.yml](../src/main/resources/config.yml) 是 `settings.spawn-on-join: true` + `spawn: { }`（空）。
未执行过 `/setspawn` 时，`getString("spawn.world")` 返回 **null**；而 `Bukkit.getWorld(null)` **不会返回 null，
而是直接抛 `IllegalArgumentException(name cannot be null)`**。于是 `if (world == null)` 这道防线永远到不了——
玩家每次进服都会抛异常（被 Paper 吞为事件报错，不影响其它插件，但日志报错且 spawn-on-join 失效）。

> 1.0.0 加固时（见 [note/hardening.md](../hardening.md) 四.2）加了 `world == null` 判空，但漏判了
> “getWorld(null) 是抛异常而非返回 null”，本轮补全。

## 修复

两处读取点都改为**先取字符串、判空后再查**：

```java
String worldName = plugin.getConfig().getString("spawn.world");
World world = worldName == null ? null : Bukkit.getWorld(worldName);
if (world == null) { ... }   // 现在：未设置出生点 / 世界未加载 / 名字拼错 都安全落到这里
```

- `BEListener.onPlayerJoin`：未设置出生点时静默 return（不再传送、不报错）。
- `SpawnCommand`：未设置出生点时给玩家“无出生点设置”提示。

全仓审计：其余 `getWorld()` 均为 `Block`/`Entity`/`Location` 的实例方法（不接受名字、不会触发此异常），
仅这两处用静态 `Bukkit.getWorld(String)`，均已修复。`SetSpawnCommand` 只写不读，无需改。
