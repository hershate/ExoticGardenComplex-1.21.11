# ExoticGardenComplex 1.1.0（Minecraft 1.21.11）

> 发布日期：2026-07-31
> 目标 Minecraft：1.21.1 ~ 1.21.11（paper-api 1.21.1，Java 16 编译 / JDK 21 构建）
> 依赖：粘液科技 REF（`com.github.slimefun:Slimefun:4.9.5`，第三方非官方分支 [hershate/Slimefun4.1](https://github.com/hershate/Slimefun4.1)）
> 产物：`ExoticGardenComplex-1.21.11-1.1.0.jar`
> 静态测试：9 维度 50/50 通过；离线基准：三项等价性断言全 PASS。

**性能优化版本**。在 1.0.0（编译适配 + 三轮安全/稳定性加固）基础上，针对本插件自身算法层
热点做优化，**不降低安全性/稳定性/兼容性、不改变玩家可见行为**。

## 改动概要（详见 [note/perf-optimization.md](../perf-optimization.md) 与 [report/perf](../report/perf/2026-07-31-perf-optimization.md)）

### 机器 ticker（DefaultGUI / ThreeInputGUI）
- **输入签名缓存**：idle 机器输入未变时跳过全量配方匹配（稳态常态）。基准命中稳态 **10.58×**、空输入 **25.49×**。
- 缓存槽位常量、复用 BlockMenu、单次解析 SF 物品（原 3 次 `BlockStorage.check` → 1 次）、
  `int[]` 替代 `HashMap`、ThreadLocalRandom、progressBar/subRecipes 懒缓存。

### MachineIO.fits
- int 金额模拟，零 `ItemStack.clone`。基准 **2.89×**。

### 采集 / 监听器
- berry/tree O(1) 索引（`harvestPlant` 及各监听器循环）。基准 berry 查表 **61×**。
- `dropFruitFromTree` 加 PLAYER_HEAD 过滤（跳过 ~26/27 个非头方块的 `BlockStorage.check`）。
- 配置（blacklist/chances/autoGenerate）与草掉落数组缓存。

### 测试基建
- 新增 `benchmark/` 离线基准（纯 Java、无 Bukkit 依赖），含新旧算法移植与 20 万级等价性断言，
  量化前后差异（`bash benchmark/run.sh`）。
- `test/test.sh` 新增“基准正确性”检查维度。

## 构建与测试

```bash
# 1. 一次性安装 REF 到本地仓库
cd REF/Slimefun4.1 && mvn clean install -DskipTests
# 2. 编译附属 → target/ExoticGardenComplex-1.21.11-1.1.0.jar
cd ../.. && mvn clean package -DskipTests
# 3. 静态测试（含基准正确性）
bash test/test.sh
# 4.（可选）运行基准并保存结果
bash benchmark/run.sh save
```

## 兼容性

- 公开 API（`getInputSlots`/`getOutputSlots`/`fits`/`pushMainItems`/`getSubRecipes`/
  `getProgressBar`、配置文件格式、物品/配方 id 等）**完全不变**。
- 配置缓存因本附属无 reload 机制而与原“每次读内存快照”等价。
- 离线基准三项等价性断言（match / fits）全 PASS，证明行为不变。
