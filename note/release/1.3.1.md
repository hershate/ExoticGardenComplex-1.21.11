# ExoticGardenComplex 1.3.1（Minecraft 1.21.11）

> 发布日期：2026-08-02
> 目标 Minecraft：1.21.1 ~ 1.21.11（paper-api 1.21.1，Java 16 编译 / JDK 21 构建）
> 依赖：粘液科技 REF（`com.github.slimefun:Slimefun:4.9.5`，第三方非官方分支 [hershate/Slimefun4.1](https://github.com/hershate/Slimefun4.1)）
> 产物：`ExoticGardenComplex-1.21.11-1.3.1.jar`
> 静态测试：10 维度 51/51 通过；离线基准：10 项等价性断言全 PASS。

**实机测试发现的问题修复版本**。修复在他人受保护领地内破坏草丛时掉落种子、并由此导致服务端**延时极高（主线程严重卡顿）**的问题。

## 问题（实机测试发现，2026-08-02）

在他人受保护领地（如 Residence / 其它“还原式”领地插件）内破坏草丛（`SHORT_GRASS`）时：**只要掉出一颗种子，服务端延时立刻变得极高**（主线程卡顿，非堆积累压）。

经与报告者核实的关键事实：

- **仅在保护区出现**：在非保护区 / 自己的地正常破坏草丛（草不被还原、种子正常掉落）**不会**卡顿。
  因此卡顿不是“种子掉落”本身的问题，而是“**种子掉落在草被还原的位置**”这一交互所致。
- 报告者**并未**进行“无限刷”（单次破坏即触发卡顿）。

### 根因（掉落为何会在保护区发生）

1. **掉落门禁无法识别 Residence**：[PlantsListener.onHarvest](../src/main/java/io/github/thebusybiscuit/exoticgarden/listeners/PlantsListener.java) 草种子掉落分支唯一门禁是
   `Slimefun.getProtectionManager().hasPermission(player, loc, BREAK_BLOCK)`。而 REF（`Slimefun 4.9.5`）**全源码无任何 `residence` 引用**——
   Slimefun 的 `ProtectionManager` 不对接 Residence；[ExoticGarden.isResidenceEnabled()](../src/main/java/io/github/thebusybiscuit/exoticgarden/ExoticGarden.java)
   （`onEnable` 仅置一个布尔标志）**从未被读取**（死代码）。故领地内门禁仍返回 `true`。
2. **当帧掉落 + 事件时序**：`BlockBreakEvent` 在方块实际移除**之前**派发；该领地插件以“还原方块”（而非取消事件）方式保护——
   本事件结束后把草放回。原实现当帧即 `dropItemNaturally`，于是出现“草被还原、种子已落在该位置”。
3. **卡顿的精确逐 tick 机制未能在静态分析中确定**：本插件掉落路径**不存在**递归 / 大量分配 / 异常（事件异常被 Bukkit 吞为日志；
   掉落物均为合法 `ItemStack`——`PUMPKIN_SEEDS`/`MELON_SEEDS`/`OAK_SAPLING` 等，无玩家头；全仓无 `ItemSpawn/EntitySpawn/ItemMerge` 回调）。
   故“种子 + 草还原位置”为何令主线程延时极高，推测发生在 Bukkit/Paper/Slimefun/领地插件对“还原位置上的物品实体”的处理侧，
   超出本附属源码可静态确定的范围。**但触发条件明确：领地内掉落的这颗种子。**

> 附带收益：同一缺陷在原理上也允许“破坏 → 草还原 → 再破坏”反复掉种子（无限刷），本次修复一并堵死。

## 修复

将草种子掉落从“事件当帧直接掉落”改为**延迟到下一 tick 并校验方块确为 air 才掉落**（[dropGrassSeeds](../src/main/java/io/github/thebusybiscuit/exoticgarden/listeners/PlantsListener.java)）：

- `BlockBreakEvent` 末尾用 `Bukkit.getScheduler().runTask(plugin, ...)` 调度到下一 tick；
- 下一 tick 时若 `grassBlock.getType().isAir()` 为真（草确实被破坏、未被还原）才掉落；
- 若领地保护把草还原回去（方块仍非 air），直接 `return`，**不掉落**——还原式保护下种子不再出现在“被还原的位置”，卡顿触发条件被消除。

附带加固：
- 掉落物一律 `ItemStack.clone()`，避免修改 [ExoticGarden.getGrassDrops()](../src/main/java/io/github/thebusybiscuit/exoticgarden/ExoticGarden.java) 中共享的掉落池实例（数组缓存 / map 值）；
- 数组掉落项追加 `!= null && !isAir()` 防御。

## 行为兼容性

- **正常破坏草丛**（非保护区）：下一 tick 方块已是 air，与原先一样掉落（仅晚 1 tick ≈ 50ms，玩家无感）；创造模式、空掉落池等条件不变。
- 植物采摘（`else` 分支 / `harvestPlant`）、树果掉落（`dropFruitFromTree`）等其余路径**完全未改**。
- 公开 API、配置格式、物品/配方 id **不变**。
- 离线基准 10 项等价性断言全 PASS（本路径为 Bukkit 事件依赖，未纳入算法层基准；改动仅是“何时掉落”的时序与 air 校验，不改变掉落概率与物品集合）。

## 待实机回归（重要）

本仓库一贯**仅做源码层编译 + 静态测试，未做实机运行回归**（见 [testing.md](../testing.md) 5）。本次：

- **逻辑上确定**：领地内不再掉落草种子（草还原 → 非 air → `return`），故“种子落在被还原位置”这一卡顿触发条件被消除。
- **需实机确认**：服务端延时是否随之恢复正常。**建议上真实 Paper 1.21.1+ 服务器（装 REF 编译的 Slimefun + 本附属 + 对应领地插件）复测**：
  在他人领地内破坏草丛应不再掉落种子、不再卡顿；正常草地破坏照常掉落。
- **若卡顿仍复现**：可能该领地插件的“还原”是**延迟还原**（晚于 1 tick 才把草放回），此时下一 tick 方块仍为 air、会被误判为已破坏而掉落。
  此种情况请反馈，可改为更长延迟的二次校验。亦请附上卡顿时段的 `logs/latest.log` 与 `/timings on` 报告，以定位是否另有独立根因。
