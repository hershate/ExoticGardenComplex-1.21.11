# ExoticGardenComplex 1.3.1（Minecraft 1.21.11）

> 发布日期：2026-08-02
> 目标 Minecraft：1.21.1 ~ 1.21.11（paper-api 1.21.1，Java 16 编译 / JDK 21 构建）
> 依赖：粘液科技 REF（`com.github.slimefun:Slimefun:4.9.5`，第三方非官方分支 [hershate/Slimefun4.1](https://github.com/hershate/Slimefun4.1)）
> 产物：`ExoticGardenComplex-1.21.11-1.3.1.jar`
> 静态测试：10 维度 51/51 通过；离线基准：10 项等价性断言全 PASS。

**实机测试发现的问题修复版本**。修复在他人受保护领地内破坏草丛触发“无限刷种子”，并由此可能拖垮服务端的问题。

## 问题（实机测试发现）

在他人受保护领地（如 Residence）内破坏草丛（`SHORT_GRASS`）时：

1. **种子掉落判定被触发**：[PlantsListener.onHarvest](../src/main/java/io/github/thebusybiscuit/exoticgarden/listeners/PlantsListener.java) 的草种子掉落分支原本在 `BlockBreakEvent`（`EventPriority.MONITOR`）当帧直接掉落，唯一门禁是
   `Slimefun.getProtectionManager().hasPermission(player, loc, BREAK_BLOCK)`。
2. **该门禁无法识别 Residence**：REF（`Slimefun 4.9.5`）**全源码无任何 `residence` 引用**——Slimefun 的 `ProtectionManager` 不对接 Residence；
   [ExoticGarden.isResidenceEnabled()](../src/main/java/io/github/thebusybiscuit/exoticgarden/ExoticGarden.java)（`onEnable` 中仅置一个布尔标志）也**从未被读取**（死代码）。
   故在 Residence 领地内 `hasPermission` 仍返回 `true`，掉落分支照常执行。
3. **草被还原 → 无限刷**：`BlockBreakEvent` 在方块实际移除**之前**派发；Residence 等以“还原方块”（而非取消事件）方式保护领地的插件，会在本事件结束后把草放回。
   于是出现“草被还原、种子已掉落”，玩家可无限重复破坏 → 无限刷种子。
4. **可能拖垮服务端**：高频重复触发（破坏 → 还原 → 再破坏）会在同一位置持续产生方块更新与物品实体；本插件**不存在任何**会让单次掉落“立刻崩溃”的递归/异常路径
   （事件处理器异常会被 Bukkit 吞为日志而非崩溃；掉落物均为合法 `ItemStack`；全仓无 `ItemSpawn/EntitySpawn/ItemMerge` 等回调），
   故唯一能真正令服务端**崩溃**（而非仅报错）的机制是**资源耗尽 / 主线程阻塞**（物品实体堆积、OOME 或 Paper watchdog 强杀）。
   崩溃后这些已落盘的物品实体在玩家重连、对应区块重新加载时会再次被处理，表现为“重连后延时崩溃”。

## 修复

将草种子掉落从“事件当帧直接掉落”改为**延迟到下一 tick 并校验方块确为 air 才掉落**（[dropGrassSeeds](../src/main/java/io/github/thebusybiscuit/exoticgarden/listeners/PlantsListener.java)）：

- `BlockBreakEvent` 末尾用 `Bukkit.getScheduler().runTask(plugin, ...)` 调度到下一 tick；
- 下一 tick 时若 `grassBlock.getType().isAir()` 为真（草确实被破坏）才掉落；
- 若领地保护把草还原回去（方块仍非 air），直接 `return`，**不掉落**——任何“还原式”保护都无法再触发掉落，无限刷漏洞被堵死。

附带加固：
- 掉落物一律 `ItemStack.clone()`，避免修改 [ExoticGarden.getGrassDrops()](../src/main/java/io/github/thebusybiscuit/exoticgarden/ExoticGarden.java) 中共享的掉落池实例（数组缓存 / map 值）；
- 数组掉落项追加 `!= null && !isAir()` 防御。

## 行为兼容性

- **正常破坏草丛**：下一 tick 方块已是 air，与原先一样掉落（仅晚 1 tick ≈ 50ms，玩家无感）；创造模式、空掉落池等条件不变。
- 植物采摘（`else` 分支 / `harvestPlant`）、树果掉落（`dropFruitFromTree`）等其余路径**完全未改**。
- 公开 API、配置格式、物品/配方 id **不变**。
- 离线基准 10 项等价性断言全 PASS（本路径为 Bukkit 事件依赖，未纳入算法层基准；改动仅是“何时掉落”的时序与 air 校验，不改变掉落概率与物品集合）。
