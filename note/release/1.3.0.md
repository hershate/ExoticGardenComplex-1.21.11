# ExoticGardenComplex 1.3.0（Minecraft 1.21.11）

> 发布日期：2026-08-01
> 目标 Minecraft：1.21.1 ~ 1.21.11（paper-api 1.21.1，Java 16 编译 / JDK 21 构建）
> 依赖：粘液科技 REF（`com.github.slimefun:Slimefun:4.9.5`，第三方非官方分支 [hershate/Slimefun4.1](https://github.com/hershate/Slimefun4.1)）
> 产物：`ExoticGardenComplex-1.21.11-1.3.0.jar`
> 静态测试：10 维度 51/51 通过；离线基准：9 项等价性断言全 PASS。

**性能优化 + 稳定性修复版本**。在 1.2.1 基础上针对事件驱动高频路径与机器能量路径做优化，
**不降低安全性/稳定性/兼容性、不改变玩家可见行为**；过程中发现并修复了机器能量消耗的一个稳定性 Bug。

## 改动概要（详见 [note/perf-optimization.md](../perf-optimization.md) 七 与
[report/perf](../report/perf/2026-08-01-perf-optimization-2.md)）

### 机器能量消耗路径（DefaultGUI / ThreeInputGUI）—— 稳定性修复 + 性能优化
- **修复 Bug**：原 `component.addCharge(b.getLocation(), -getEnergyConsumption())` 在 REF（4.9.5）的
  `addCharge` 中因 `Validate.isTrue(charge > 0)` 抛 `IllegalArgumentException`（负数）——**所有可充能机器
  （种子分析机 / 酒曲培养机 / 电力酿造机 I/II/III）每加工 tick 必抛异常、且不消耗能量**。改为
  `getCharge(loc,data)` + `setCharge(loc,data,charge-consumption)` 的单次读路径，机器现在真正按
  `getEnergyConsumption()` 消耗电力（设计意图）。
- **性能**：原等价路径（`removeCharge`）内部重复 `getCharge`（又一次 `BlockStorage.getLocationInfo`）；
  改用 `Config` 重载复用同一次查询，**少一次 BlockStorage 查询**。新增 `locationCache` 按方块缓存
  `Location`，**零稳态分配**（原每 tick 2 次 `b.getLocation()`）。
- 离线基准仅保留**正确性等价断言**（单次读+`setCharge` 与 `removeCharge` 完全等价）；计时因 sim 的
  `getLocationInfo` 可被 JIT CSE 而无法忠实量化，详见 report。

### SlimefunTag 材质判定（PlantsListener.onInteract，每次右键）
- 原“遍历全部 `SlimefunTag.values()` 逐一 `isTagged`”（O(标签数)）改为按 `Material` 记忆化（O(1)）。
  `SlimefunTag` 加载后不可变，结果可永久缓存。基准 **84.3→5.4 ns（约 15.6×）**。

### 物品解析（Berry.getItem / getBushItem，采集 + 植物生长）
- `Berry.getItem()`（每次 `SlimefunItem.getById(id).getItem()`）与 `harvestPlant` 的 `getItem(toBush())`
  改为 `Berry` 上的懒缓存字段。基准（getItem：注册表查找 vs 缓存字段）**10.9→3.7 ns（约 2.9×）**。

### getByItem 物品识别（FoodListener.onUse，每次交互）
- `getByItem(CustomItemStack.create(hand, 1))` 改为直接 `getByItem(hand)`：REF 的 `getByItem` 只读 Material + PDC
  （SF id），不读 amount，故克隆多余。基准（先 clone vs 直接）**31.2→13.5 ns（约 2.3×）**。

### 测试基建
- `benchmark/` 新增 SlimefunTag / getItem / getByItem / 能量结算四组新旧对照与四项正确性断言
  （离线等价性断言由 5 项增至 **9 项**）。

## 构建与测试

```bash
# 1. 一次性安装 REF 到本地仓库
cd REF/Slimefun4.1 && mvn clean install -DskipTests
# 2. 编译附属 → target/ExoticGardenComplex-1.21.11-1.3.0.jar
cd ../.. && mvn clean package -DskipTests
# 3. 静态测试（含基准正确性）
bash test/test.sh
# 4.（可选）运行基准并保存结果
bash benchmark/run.sh save
```

## 兼容性

- 公开 API（`getInputSlots`/`getOutputSlots`/`fits`/`pushMainItems`/`getSubRecipes`/`getProgressBar`、
  `Berry.getItem()`、配置文件格式、物品/配方 id 等）**完全不变**。
- 能量修正使机器按设计消耗电力，属修复设计意图，非行为回退。
- SlimefunTag 记忆化与 getItem 缓存均为内部实现替换，对玩家可见行为无影响。
- 9 项离线等价性断言全 PASS，证明行为不变。

## 已知遗留（同 1.0.0~1.2.1）

- BEPlants ROSE/REED texture 哈希截断（头显异常），保留注册防对应 Juice 配方变空。
- 加工中被破坏的机器损失材料（与原版 Slimefun 一致）。
- 未做实机运行回归；**1.3.0 重点建议**验证电力酿造机 / 种子分析机 / 酒曲培养机通电后是否正常耗电并推进
  （修复了此前“有电即抛异常、不耗电”的 Bug）。
